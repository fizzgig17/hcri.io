TKLamp Live Logger

Last updated October 27, 2026 · Works on Windows, macOS and Linux · Download tklamp_live.py

01 What it does

The TKLamp TK2303D tester sends its lumen reading over USB about four times a second while it is on. This small Python script listens to that stream on your computer, shows the live number, records a run on the computer's clock, and uploads the finished run to your Runtime list on hCRI.io.

Why use it instead of Transfer Data?

The tester's own Transfer Data sends the stored readings after the test, with no date or time, so the real start and end of the run are unknown. Because this script records while the test is running, the start time, end time and length are exact. You choose the name, and it can upload and make a share link for you.

Prefer your phone?

hCRI Companion does the same with the ESP32 bridge, no computer needed. See Using a TKLamp tester and the manual.

02 Install

  1. Install Python 3From python.org if you do not have it. On Windows, tick "Add Python to PATH" in the installer.
  2. Install the serial libraryOpen Terminal (Mac) or Command Prompt (Windows) and run pip install pyserial.
  3. Download the scripttklamp_live.py. Save it in a folder you will find again, such as Documents.
  4. Plug in the testerConnect the tester's USB cable to the computer and switch the tester on. It must be on and sending readings. The computer sees it as a CH340 USB serial device. Windows may need the free CH340 driver if no port appears; recent macOS and Linux include it.

03 Connect to hCRI.io (optional)

To upload from the script it needs an API token, the same kind hCRI Companion uses. The script can create one for you, the same way Companion's Settings does.

  1. Sign in onceRun python tklamp_live.py --login. Enter your hCRI.io email or username and password (the password is not shown). The script signs in, creates a token named "TKLamp logger (your computer)" and remembers it in a file in your home folder (.hcri_tklamp.json), readable only by you. Your password is sent only to hCRI.io, once, and is never saved or printed.
  2. Or let it askIf you finish a run with no token saved, the script offers to sign in right then, and uploads straight after.
  3. Or paste a tokenMake one on hCRI.io (account settings, API tokens, Create token) and run python tklamp_live.py --token YOUR_TOKEN --save-token, or set the HCRI_TOKEN environment variable.

Keep the token private

Anyone with the token can add curves to your account. Do not paste it into a chat, a screenshot or a shared file. You can delete a token from your account settings at any time.

04 Record a run

  1. Start the scriptRun python tklamp_live.py. It finds the tester's port by itself (or asks you to pick one; you can also give --port COM5 or --port /dev/tty.usbserial-1420). The live lumens appear on one line.
  2. Put the light in the sphereWait until the number looks right.
  3. Press Enter to startThe line shows REC with the elapsed time and the number of readings. The start time is taken from your computer's clock.
  4. Press Enter again to stopOr use --duration 30 to stop by itself after 30 minutes. Ctrl+C also stops and keeps what was recorded. While recording, a .partial.csv copy is written every couple of seconds, so a crash does not lose the run.

Keep the computer awake and the cable in for the whole run. For a 24 hour run, turn off sleep first.

05 After the run

  1. Check the summaryIt shows the length, the number of readings, the first and last lumens, and the exact start and end times. The dark readings before the light came on are trimmed (use --no-trim to keep them).
  2. Name itPress Enter to accept the suggested name (TKLamp run 2026-10-27 18:00) or type your own. The same name on hCRI.io replaces an earlier run.
  3. UploadIf a token is set it asks whether to upload to Runtime. Answer Y. The run appears in Explore, then Runtime, as a private curve.
  4. Share (optional)It asks whether to make a share link and prints it. Anyone with the link can view the run without signing in. You can stop sharing from the light's page.

If the upload fails, or you said no, the run is already saved. Upload it later with python tklamp_live.py --upload TKLamp_2026-10-27-18.00.00.json, or use Upload CSV on the Runtime page with the saved .csv.

06 Calibrating the scale

The tester sends a raw sensor count, and the script divides it by counts per lumen to show lumens. The default, 313.2, was measured on one calibrated tester using its 2150 lm calibration lamp. Each tester, and each recalibration, can differ a little.

To set it for yours, put a lamp of known output in the sphere, wait for it to settle and run python tklamp_live.py --calibrate 2150 (use the lamp's lumens). It reads for 8 seconds, shows the new scale and saves it. This is the same as Set scale in hCRI Companion.

07 All options

OptionWhat it does
--port PORTSerial port, if it is not found automatically.
--calibrate LUMENSSet and save the scale from a lamp of known output.
--scale NUse this counts-per-lumen for this run only.
--duration MINStop by itself after this many minutes.
--no-trimKeep the dark readings before the light came on.
--output-dir DIRWhere to save runs (default: the current folder).
--loginSign in with your hCRI.io email/username and password, create a token and remember it.
--token T, --save-tokenUse an API token you made on the website, and remember it.
--site URLAnother hCRI.io address (default https://hcri.io).
--upload FILE.jsonUpload a run saved earlier, then exit.
--simulateNo tester needed: a made-up fading light, to try the script.

08 The files it saves

  • TKLamp_<date>.json: the run (name, spacing, lumens) plus its start and end times, length, number of readings and the scale used.
  • TKLamp_<date>.csv: minutes in the first column and the lumens in the second, ready for Upload CSV on the Runtime page.

Runs are stored at one point per second (wider spacing beyond about 27 hours, hCRI.io's 100,000 point limit). hCRI.io does not store the start and end times yet, so they stay in the saved .json.

09 Troubleshooting

SymptomTry
"No serial ports found"Check the USB cable is a data cable and the tester is plugged in. On Windows, install the CH340 driver.
"no readings (tester on? cable in?)"Switch the tester on and leave it sending. If it is a different port, use --port.
"pip is not recognised"Try python -m pip install pyserial (or py -m pip ... on Windows).
Permission denied on LinuxAdd yourself to the dialout group, then log out and in.
The number differs from the tester's screenRun --calibrate with a lamp of known output.
"Sign-in failed: Invalid credentials"Check the email or username and password. You can also make a token on the website and use --token.
"hCRI.io said 401"The token is wrong or was deleted. Run --login again to create a new one.
The upload says the account limit is reachedDelete some runtime curves on hCRI.io, then upload again with --upload.

Using the tester's own Transfer Data instead? The manual and the Runtime page's Upload CSV explain how to set the seconds between readings for that file.
